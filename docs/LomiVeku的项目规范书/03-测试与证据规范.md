# 03 测试与证据规范（T 系列）

> 版本 v1.0｜2026-10-19｜适用范围：所有项目｜上位文件：README（十条铁律）

编号说明：**测试层级**用无连字符的 `T0`–`T4`，**规则条目**用带连字符的 `T-01` 起，二者互不引用。

## 3.1 五层测试

| 层 | 名称 | 时机 | 执行 | 通过标准 |
|---|---|---|---|---|
| **T0** | 单元测试 | 每批代码改动后 | 实施方 | 全绿；用例用独立临时目录，不共享状态、不依赖顺序 |
| **T1** | 应用内自检 | 每次构建 / 每批交付 | 实施方全跑 + 复核方独立复跑 | 全部通过；项数 ≥ 适配表下限；不删项、不降阈值 |
| **T2** | 对照验证 | 新增或修改断言时 | 实施方造对照缺陷版，复核方核验 | 缺陷版**必须失败**；无对照的断言不验收 |
| **T3** | 端到端 | 发布物变更（安装 / 便携 / 卸载 / 升级） | 主控或指定复核方独立复测 | 装卸三清、哈希三方一致、资源实测、数据保留、干净性 |
| **T4** | 独立测试 | 重大迭代 / 主要发布前 | 异源主体 | 独立设计、独立执行；问题逐一闭环 |

层的选择：改动越靠近用户可见行为与产物形态，越要往高层走；只跑 T0/T1 就交付，等于没验证"交到别人手里还成不成立"。

## 3.2 断言纪律（14 条）

**T-01｜双向可判别**：任何新增断言都必须用"对照缺陷版"（同源、仅注入目标缺陷）证明其能失败；能在同一条断言内同时验证正例与反例的，优先自含，不另做对照构建。理由：只会通过的检查不具备判别力，它打印的 PASS 与"没检查"等价；自含双向还省一次构建、少一处版本漂移。落地：对照缺陷版与产物一并留档；未附对照的断言在评审时直接退回；自含式断言在报告中说明哪一半是负向。

**T-02｜不硬编码素材常量**：断言的期望值必须取自运行时真值（实测尺寸、数量、哈希），不得写死素材常量。理由：素材一换，硬编码断言要么静默失效，要么报假失败，两种结果都比没有断言更糟。落地：断言内出现具体数字时，必须能指出该数字的来源函数或来源文件。

**T-03｜未触发态用例**：交互、几何、阈值类改动必须覆盖"未触发"的否定用例。理由：符号翻转、边界误判这类缺陷在"已触发"路径上表现完全正常，只有中立位才能暴露。落地：每条触发型逻辑至少配一条"不该触发时不触发"的用例。

**T-04｜场景前提成立**：测试场景必须真正满足断言的前提（测"极端条件下保持"就必须构造极端输入）。理由：前提不成立的场景会得出"通过"，而这个通过证明的是另一件事。落地：断言注释写明前提；报告列出本批实际使用的场景参数；视觉类（半透明、多主题、自适应配色）另须覆盖两极条件——黑↔白背景、明↔暗主题、最小↔最大缩放，极值写入适配表。

**T-05｜被测物定位正确**：必须明确本轮验证的是哪一份副本，并在报告中写出其路径与哈希。理由：同名多副本（构建目录、交付目录、临时副本）极易测错对象。落地：测试命令写全路径；产物须放在运行时期望的相对位置，否则测到的是兜底路径而非正常路径。

**T-06｜截图口径**：截图必须说明取的是屏幕区域还是渲染区域；屏幕级截图要求被测窗口完整在屏内，否则内容为空或发黑；像素类结论以结构断言为主、像素佐证为辅。理由：截图坐标含装饰偏移、受缩放影响，口径不明时两张图无法比较。落地：截图文件名含日期与场景，报告中注明截图方式，并注明截图时的 DPI / 缩放与主题状态；UI 变更批的最低证据 = 改前 / 改后**同构**对比图 + 最不利小尺寸抽验。

**T-07｜屏蔽真实环境事件**：自检期间必须屏蔽真实输入（光标移动、悬停、前台切换、系统通知），并声明已屏蔽。理由：真实事件会覆盖被测状态，造成偶发失败或偶发通过，二者都无法复现。落地：自检模式显式置位；报告写明屏蔽了哪些事件源。

**T-08｜双层证据**：应用层证据（脚本注入、渲染层事件）只能证明"逻辑上点到了"，不能证明"用户真的点得到"；凡涉及遮挡、层级、焦点、其他程序抢占输入的结论，必须另补系统层证据（真实命中测试、独立探针窗口、只读属性查询）。理由：两层之间隔着窗口管理器，应用层永远看不到它。落地：报告分栏列两层证据，缺一层即标注"该结论仅覆盖应用层"；手段优先级为只读查询 > 截图断言 > 落盘断言 > 人工目测，能用只读查询证明的不要用模拟操作去撞。

**T-09｜确定性先行**：归因前先做确定性验证——重复多次、变换单一环境变量、输出逐字节比对，并**列明本次改变了哪些变量**；结论标注置信度（实测 / 文档 / 推断）。理由：一次运行的差异可能来自偶发、缓存或环境污染，直接归因是把噪声当信号。落地：报告写"重复 N 次、变量为 X、输出是否逐字节一致"；置信度为"推断"的结论不得作为修复依据。

**T-10｜假通过检查**：判定通过后，必须反问"这个通过是不是由边界值、默认值、钳制逻辑或断言自身缺陷造成的"。理由：假通过不产生任何告警，会让缺陷带着绿灯出厂，比假失败危险一个量级。落地：对"恰好等于阈值/零/默认值"的结果做敏感性分析；报告单列"未覆盖事项"，防止"没测"被读成"测过没问题"。

**T-11｜代理指标三要素**：用间接量（像素计数、耗时、体积）替代直接状态判断时，必须同时具备归因隔离、控制组、双向阈值。理由：缺任一项，指标变化都可能来自无关因素，结论不可证伪。落地：归因隔离=限定区域或通道；控制组=无操作基线；双向阈值须由已知真值标定。能用状态断言就不用代理指标。

**T-12｜轮询到截止**：禁止固定时长等待；改为轮询到截止时间，截止 = 期望时长 + 容差（容差按实测最坏值比例取），并设总预算与单项截止两级。理由：固定等待在机器负载高时必然假失败，在空闲时又白等。落地：动效类必须测两端点（起始与到期），防止"从未开始"被判为"已完成"；单项截止 ≤ 总预算 ÷ 轮询项数，超过即判该项失败（不是"告警"）。

**T-13｜串行执行与显式退出码**：自动化任务串行执行，显式等待退出码再启动下一个，结束后检查残留实例。理由：并行实例会互抢前台、互踩数据目录，产生无法复现的失败。落地：报告附每个任务的退出码；非零退出码不得当作"警告"忽略。

**T-14｜只增不删**：断言项数设下限；**下限取上一批的实际项数**（取本批会造成判据自指失效），本批只允许 ≥ 下限；不得删除断言、不得下调阈值、不得把失败项改为跳过。理由：删一条断言只需一秒，重造它需要重新踩一遍坑；下限同时是"是否跑了新版"的判据。落地：适配表填的是"上一批项数"而非"当前项数"；项数低于下限即判失败（疑似旧产物）；确需作废的断言改为"永久跳过 + 注明取代条目"，仍计入总数。

## 3.3 证据与留档

**T-15｜文本为纲**：证据以命令与输出原文为主，截图与录屏为辅；每条结论必须能指回一段可复制的输出。理由：文本可检索、可 diff、可哈希；图像只能靠人眼看，无法批量复核。落地：证据按批次分文件夹，每份首行写命令。

**T-16｜时刻与来源**：每份证据带产生时刻与来源标识（运行 ID、批次号、执行者）；引用他批证据必须核对时效，过期证据不得当新证据用。理由：证据的价值与时间强绑定，三天前的截图无法证明今天的产物。落地：证据文件名含日期；跨批引用附哈希比对结果。

**T-17｜哈希锚定与测后复核**：构建输出、包装内、部署位三处哈希必须一致；测试完成后重新计算被测物哈希，确认测试过程未修改它。理由：三方一致是唯一能机械证明"交付的就是构建的那个"的手段；部分测试会写配置、生成缓存、改权限，被测物一旦变动，前面的结论就不再对应交付物。落地：报告列出三处路径与哈希；测试前后各记一次，不一致则整批结论作废并说明原因。

## 3.4 测试环境红线

**T-18｜七条红线**：①不动物理光标（禁止直接设置光标位置或注入系统级输入）；②不抢前台焦点；③不在用户可能正在使用的时段跑自动化；④不向被测应用之外的窗口发事件；⑤破坏性操作隔离在沙箱或独立目录；⑥被测副本只读运行（**例外**：从交付位复跑自检时允许执行，但所有输出必须落在交付目录之外，并以 T-17 的测后哈希复核兜底）；⑦测试者必须敢报失败与误报，不得为了让交付通过而放水（**判定口径**：复测时若发现已放行的失败项被隐瞒，即视为违反）。理由：前六条保护用户与其他程序，第七条保护整个体系——放水一次，此后所有绿灯都不可信。落地：每条红线在方案里显式声明；例外（如经授权的真装真卸）须满足"授权在案、证据留痕、收场动作披露"。

## 3.5 交付门禁通用清单

| # | 门禁项 | 判定 |
|---|---|---|
| 1 | T0 / T1（适用时）全绿，且由复核方独立复跑 | 退出码为 0，项数 ≥ 下限 |
| 2 | 涉断言变更时 T2 对照通过 | 对照缺陷版失败 |
| 3 | 交付体检脚本通过 | 退出码 0；PARTIAL 不放行 |
| 4 | 产物哈希三方一致，命名与文档一致 | 构建 / 包装 / 部署位相同；报告引用的文件名与产物逐字相同 |
| 5 | 资源实测 | 图标、版本信息等嵌入资源可被系统实际加载，非仅存在 |
| 6 | 数据保留 | 安装、升级、卸载后用户数据完整 |
| 7 | 干净性 | 无测试数据、无日志、无缓存混入交付物 |
| 8 | 证据与报告落盘 | 路径可访问，含时间与来源 |
| 9 | 旧版已归档、登记表已更新 | 归档包可解压，登记行状态正确 |

门禁项只增不减；新增项须按 D-11 走异源检验后才生效。

## 3.6 何时必须启动独立测试

命中任一条即必须由异源主体执行 T4，不得以自检替代：①主要发布（对外首次发布或主版本升级）；②涉及用户数据的操作路径变更（安装、升级、卸载、迁移、清理）；③上一批交付被判定为故障并已接管修复；④交付物形态变化（打包方式、运行方式、依赖分发方式）。

判据是"能不能说清失败会怎样"——说不清就测，不必等命中条款。

## 3.7 修复批的回归要求

**T-19｜修复必带最小回归集**：缺陷修复批必须定义并执行最小回归集——①该缺陷的对照缺陷版（先证旧断言能失败，再修）；②受影响的相邻断言；③主流程冒烟。理由：只修不回归，等于把"这次好了"当成"别处没坏"，而修复本身最容易碰坏相邻逻辑。落地：批报告单列"回归范围 + 为什么是这些"，未列即视为未回归；同类缺陷的回归集沉淀进适配表，下次直接复用。

**T-20｜观感类结论的取证格式**：凡以观感为判据的结论（可读、美观、协调），必须记录：评审人 + 场景条件（背景 / 主题 / 尺寸 / 缩放）+ 时刻 + 引用的适配表标准原文。理由：没有取证格式的主观标准，事后无法复核，也无法判断"当时为什么算通过"。落地：结论写入报告时附上述四项，缺任一项视为未验收。

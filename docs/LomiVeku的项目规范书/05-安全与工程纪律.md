# 05 安全与工程纪律（S / E 系列）

> 版本 v1.0｜2026-10-19｜适用范围：所有项目｜上位文件：README（十条铁律）

S 系列守"不伤害"，E 系列守"不骗自己"。共同点：违反时的后果都不是当场报错，而是**一段时间之后以别的方式出现**。

## 5.1 文件与数据边界（S）

**S-01｜用户文件默认只读**：凡用户自行另存、导出、复制的文件（含带日期的新副本），在用户未明确要求修改时一律不动。理由：用户另存的那一份往往是他正在用的工作副本，改动它等于在用户不知情时替换了他的材料。落地：需要同步修改必须先问；确认后只改被点名的那一份，并在报告里写出完整路径。

**S-02｜只改当前一份，不跨副本同步**：不主动在多个同内容副本之间同步、覆盖或删除；交付新版本时优先就地修改原文件。理由：副本的存在本身说明用户需要保留某个时点的状态，自动同步会把"备份"变成"第二份工作区"，同时消掉回退的可能。落地：确需另存时明确告知新路径，并保留改前备份。

**S-03｜删改先问、破坏需授权**：删除文件、覆盖目录、清空数据、修改系统级配置属破坏性操作，必须先取得明确授权；能用回收站式可恢复删除时优先用它。理由：破坏性操作的错误成本远高于其他操作，而"我以为那是临时文件"是最常见的事故陈述。落地：授权范围在案；操作前记录被删对象的清单与哈希；批量删除设单次数量上限。

**S-04｜过渡快照有生命周期**：迁移、替换、回滚期间保留的临时副本，必须在生成时**打上日期标记**；观察期满且无运行问题后，在下一次常规备份时清理；若观察期内接到备份任务，快照一并打包进备份并删除本地副本。理由：无期限的临时副本会永久堆积，最终让人分不清哪份是当前版本。落地：观察期默认 7 日（适配表可调）；清理前确认已有更新的可回退点。

**S-05｜删除留痕**：删除任何文件前，把对象清单与哈希写入清理记录；清理只允许"盘点 → 验证 → 删除已证实无用之物"，不允许借清理之名做重构。理由：留痕让误删可被发现、可被追回；"顺手重写"则会把一次清理变成一次无人评审的改版。落地：清理记录按日期归档；系统目录与用户数据目录不得递归删除。

**S-06｜测试不碰真实数据**：一切测试在隔离环境（沙箱、独立目录、临时副本）中进行，使用构造数据；确需真实数据时必须先取得授权并使用只读副本。理由：测试的写入路径往往没有产品级的校验与保护，一条用例就足以覆盖用户的真实记录。落地：测试环境与使用环境在路径上物理隔离；开始前确认数据目录指向临时位置。

**S-07｜数据保留必须断言**：安装、升级、卸载、迁移、清理等涉及用户数据的路径，必须有可自动执行的"数据保留"断言（操作前后比对数据内容或摘要）。理由：这类缺陷不会在开发机上出现，因为开发机上没有值得保留的数据。落地：断言覆盖"保留"与"不误删"两个方向；门禁未过不得发布。

**S-08｜破坏性操作隔离**：可能失败且难以回滚的操作（安装、卸载、格式化、批量重命名）必须先在可丢弃环境跑通，再上真实环境。理由：可丢弃环境让"失败"变成信息而不是损失。落地：隔离环境的使用与销毁写入报告；真实环境执行前留一份可回退点。

**S-09｜凭据与隐私不入产物**：密钥、令牌、账号、个人路径、内部地址不得写入源码、日志、报告与交付物；留档时对敏感字段做遮蔽。理由：这些东西一旦进入交付物或留档就等于永久公开，且很难事后确认扩散范围。落地：交付前对产物做一次敏感字符串扫描；证据中的路径与用户名按需替换为占位符。

## 5.2 编码与宿主环境（E）

**E-01｜字节级取证**：涉及字符编码、全半角、不可见字符、码位的问题，必须用字节级手段（十六进制转储、码位查询、字节比对）定案，禁止凭字形或终端回显判断。理由：小字号渲染会把全角读成半角，终端会把不可见字符显示为空白，肉眼在这个尺度上不可靠。落地：报告附十六进制片段；目测结论冲突时以字节为准。

**E-02｜构建脚本 ASCII-only**：构建、打包、发布脚本内部只用 ASCII 字符；需要中文的地方（产物名、说明文案）交给调用层或专门步骤处理。理由：脚本编码取决于执行时的宿主代码页，同一文件在不同环境下可能被截断或解析失败，且失败点常在中段、报错指向别处。落地：脚本入库前做非 ASCII 扫描；中文命名集中在一个步骤，便于定位。

**E-03｜换行符、BOM 与路径显式声明**：文本文件的换行符（LF / CRLF）、是否带字节序标记、路径分隔符风格，必须在项目内统一并写入适配表；跨工具传递时按目标工具的要求转换。理由：这三种差异不会让人眼看出问题，却会让脚本解析失败、哈希不一致、比对产生成批假差异。落地：比对前先规范化（换行符、分隔符、大小写）；新增文件类型时补一条规则。

**E-04｜中文路径分层**：源码、脚本、产物可以含中文，但**工具链内部使用的中间文件与临时目录建议用 ASCII 命名**；确需中文时，确保写入端与读取端使用同一编码。理由：编码问题的修复成本与"链路长度"成正比，中间环节越短越安全。落地：中文只出现在最外层（用户可见的产物名、文档名）。

## 5.3 度量与坐标（E）

**E-05｜多坐标系必须显式换算**：同一系统内常并存多个坐标系（物理像素、逻辑像素、页面单位、截图坐标），跨层读写必须显式声明单位并换算。理由：不同坐标系之间的差值不是常数（含装饰、缩放、标题栏），混算产生的偏移看起来像"随机错位"，极难定位。落地：变量名与断言名带坐标系后缀；"读"与"写"必须在同一坐标系内完成。

**E-06｜DPI 感知先声明**：任何读取或设置屏幕坐标、窗口尺寸的操作，前先确认执行进程的 DPI 感知状态，并声明本次使用的缩放比例。理由：非感知进程看到的是被系统虚拟化过的坐标，与感知进程相差一个缩放系数，跨进程传递必然错位。落地：坐标类证据注明"取自何种感知状态、缩放多少"；跨进程传递坐标必须带换算。

**E-07｜口径先定、数字后写**：任何几何或统计断言，先写清口径（含不含装饰、含不含阴影、统计范围、采样时刻），再写数值。理由：同一对象在不同口径下的数值都"正确"，口径不明时两组数字无法比较，也无法判定谁错。落地：口径写进断言注释与报告；口径变更视为断言变更，须重走对照验证。

## 5.4 执行与并发（E）

**E-08｜长任务后台执行且必须可超时**：可能超过常规等待上限的命令（构建、全量测试、大批量处理）一律后台执行，并设截止时间与轮询间隔，禁止无限等待、禁止拍脑袋的固定睡眠。理由：被宿主杀死的进程不会告诉你死在哪一步，留下的半成品却会被当成"构建成功"；而固定睡眠在慢机器上假失败、快机器上白等。落地：输出落盘后读退出码与尾部日志，不以"没报错"作为成功依据；超时即失败并打印当前状态；日志落盘位置写进适配表（与表 A 的构建/测试命令字段联动），不得散落。

**E-09｜单实例互斥**：需要独占资源的程序（数据目录、端口、设备）必须实现单实例互斥；测试侧同时保证串行。理由：双实例并发会互踩数据，且现象随机，几乎不可能稳定复现。落地：互斥护栏做在程序侧（锁文件），串行纪律做在流程侧，两者都要有。

## 5.5 工具链可信（E）

**E-10｜校验器先自证**：任何新写的校验脚本，必须先拿"已知正确的样本"与"已知错误的样本"各跑一次，确认前者通过、后者失败，才可用于真实对象。理由：校验器自身有 bug 时会成批误报或成批漏报，而使用者会先怀疑被测对象，白花时间修没坏的东西。落地：自证用例随脚本入库；脚本改版后重跑自证。**边界**：本条约束**作者自证**；检查项启用前的**异源检验**另按 D-11 执行——自证证明"脚本能分辨好坏样本"，异源检验证明"别人也信这个结论"，两者不可互相替代。

**E-11｜没有证据时先怀疑工具**：出现"全部失败""全部通过""差异数量异常整齐"这类结果时，第一反应应是检查工具本身（编码、分隔符、大小写、排序、截断），而不是直接归因于被测对象。理由：成批异常几乎总是批量性原因，而批量性原因多半在工具侧。落地：对可疑结果先做一次人工抽样核对，再采信。

**E-12｜集合比对先规范化**：比较两组文件、路径、名称前，先统一分隔符、排序规则、大小写与换行符；字节级疑案以十六进制转储为终审。理由：未规范化的比对会产生大量假差异，掩盖真差异。落地：比对脚本把规范化步骤打印出来。

**E-13｜可复现构建**：固定工具链版本与构建参数，产物应可重复生成；关键发布前做一次"同源重打"（同一源码再构建一次），比对两次产物是否逐字节一致或差异可解释。理由：不可复现的构建意味着"线上那一份"无法重建，出问题时只能猜测。落地：工具链版本写入适配表；重打结果与差异说明写入报告。

**E-14｜可降级路径必须保留**：为性能或兼容做的激进优化，必须保留一条可切换回退的路径，并确保该路径在代码里仍然可用。理由：优化带来的问题往往在特定环境才出现，没有回退路径时用户侧只能等新版本。落地：回退开关的存在性纳入交付检查；**开关必须有一次实测触发记录**，无记录视为该项未满足；不得在"清理代码"时顺手删掉。

**E-15｜依赖对端的链路必须有退化分支**：任何"A 等 B 回应"的流程，必须实现"B 不在"时的退化分支（超时直通、本地兜底、明确报错）。理由：对端可能未就绪、已崩溃或被系统挂起，等待型代码没有退化分支就会永久卡住。落地：为每条等待链设计并测试退化路径；退化须有可观察的日志或提示。

**E-16｜错误态与空态必须可区分**：读取失败不得被当作"没有数据"，首次使用不得被当作"读取失败"。理由：混淆两者会导致两种严重后果——要么用空数据覆盖真实数据，要么在正常空状态下反复报错。落地：状态至少分三态（成功有数据 / 成功无数据 / 失败），失败态阻断一切写入路径并给出可观察提示。

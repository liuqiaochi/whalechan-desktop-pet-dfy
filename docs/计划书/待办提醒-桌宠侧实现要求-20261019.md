## 一、必改（P0）

### Y-01 台词截断会切坏 emoji 与换行

**位置**：`src/main/todo-bridge.js` → `performRemind()`

**现状**：

```js
const text = fn(String(content).slice(0, 24), fmtOverdue(overdueBy));
```

两个问题：

1. `String.prototype.slice` 按 **UTF-16 码元**切。`🐟` 占 2 个码元，切在第 24 个位置会把代理对劈开，气泡里出现 `�`；
2. 待办的 `content` 允许换行（详情编辑是多行输入）。换行直接进气泡会把气泡撑破或截断。

**建议**：

```js
/** 台词用：压平空白 + 按码点截断 */
function clipSpeech(s, n) {
  const clean = String(s == null ? '' : s).replace(/\s+/g, ' ').trim();
  return Array.from(clean).slice(0, n).join('');
}

const text = fn(clipSpeech(content, 24), fmtOverdue(overdueBy));
```

**判据**：内容为 24 个 emoji 时不出现 `�`；内容含 `\n` 时气泡仍是一行。

## 二、建议改（P1，均为低风险小改动）

### Y-02 `overdueBy` 小于 1 分钟时的渲染兜底

**位置**：`performRemind()` 的档位选择 + `fmtOverdue()`

**现象**：`overdueBy` 在 0–59999ms 之间时，`Number(overdueBy) > 0` 成立 → 走"超期"台词，而 `fmtOverdue` 向下取整到分钟 → **"已经超期 0 分钟了"**。

我方虽然会钳制成 `0`，但这是"发送端约定"；渲染端也兜一层，任何第三方实现接进来都不会出丑。

**建议（二选一）**：

```js
// 方案 A：把 <60s 视为"刚到点"
const isJustNow = Number(overdueBy) > 0 && Number(overdueBy) < 60000;
const fn = (Number(overdueBy) > 0 && !isJustNow ? LINES_OVERDUE : LINES)[key];

// 方案 B：让 fmtOverdue 自己说人话
function fmtOverdue(ms) {
  const m = Math.floor((Number(ms) || 0) / 60000);
  if (m <= 0) return '不到 1 分钟';
  ...
}
```

**判据**：mock 发 `overdueBy=30000`，气泡不出现"0 分钟"。

### Y-03 非 Windows 平台不要启动重连

**位置**：`init()`

**现象**：`net.connect('\\\\.\\pipe\\whalechan-todo')` 在 macOS 上是一条不存在的文件路径 → `ENOENT` → 按 1s/2s/4s…30s 永久重连。功能上没错（静默降级），但会持续产生无效定时器与日志噪音，也浪费一点电。

**建议**：

```js
function init(options) {
  opts = options;
  if (process.platform !== 'win32') return;   // 待办只有 Windows 版
  statePath = path.join(options.userDataDir, 'remind-state.json');
  loadRemindState();
  connect();
}
```

**判据**：mac 上运行 24h，无 `whalechan-todo` 重连日志、无相关定时器。

---

### Y-04 未知 priority 不要静默丢弃

**位置**：`performRemind()`

**现状**：`LINES[key]` 取不到时 `fn === undefined`，直接 `return`。今天没问题（五档已定），但**将来待办侧新增档位（比如 `critical`）时，提醒会静默消失**，且没有任何日志能定位。

**建议**：

```js
const key = String(priority || 'normal');
const table = Number(overdueBy) > 0 ? LINES_OVERDUE : LINES;
const fn = table[key] || table.normal;     // 未知档位按 normal 处理
if (!fn) return;                            // 仅 shelved 这类显式静音
```

**判据**：mock 发 `priority="critical"` → 按 `normal` 台词说话，不崩、不静默。

---

### Y-05 收包缓冲加上限

**位置**：`connect()` 的 `s.on('data', ...)`

**现状**：`buf += chunk.toString('utf8')` 没有上限。正常服务端每行都有 `\n`，但一旦对面实现有 bug（或恶意），发一条永不带换行的数据流就会把内存吃满。

**建议**：

```js
const MAX_BUF = 64 * 1024;
s.on('data', (chunk) => {
  buf += chunk.toString('utf8');
  if (buf.length > MAX_BUF) {   // 超限：丢弃缓冲并断开，等重连
    buf = '';
    try { s.destroy(); } catch (_) {}
    return;
  }
  ...
});
```

**判据**：mock 连续发 1MB 无换行数据，进程内存不持续增长。

---

### Y-06 先确认窗口可用，再扣提醒配额

**位置**：`performRemind()`

**现状**：

```js
markReminded(id);                       // ← 先扣配额
const win = opts.petWindow;
if (!win || win.isDestroyed()) return;  // ← 才发现没窗口
```

窗口重建/关闭期间收到 `due`，配额会被白扣一次（当天 2 次额度少一次）。

**建议**：把 `markReminded(id)` 移到窗口可用性检查之后、`executeJavaScript` 之前。

**判据**：销毁窗口后发 `due`，`remind-state.json` 里该 id 计数不增加。

### Y-07（文案级）`loadRemindState` 的注释与实现不一致

**位置**：`loadRemindState()`

注释写"只保留今天和昨天"，代码是 `if (key !== k) delete`——只保留今天。二者留一个：要么改注释，要么保留昨天（跨零点时更稳）。不影响功能。

## 三、协议确认（不需要改代码，确认即可）

### 3.1 我方保证（v1.3.0 起）

1. 连接建立后**立即**推一条全量 `state`；
2. 待办变化后推 `state`（内容未变不推，设置项变化不触发）；
3. `due` 对同一条待办的**同一个 deadline 只推一次**；deadline 改成新时间后，到点会再推一次；
4. `priority=shelved` 的待办**不进 `due`**（但仍在 `state` 里）；
5. `overdueBy < 60000` 时传 `0`；≥60s 传实际毫秒；
6. `content` 截断到 200 字符、`items` 上限 200 条、单条消息 < 64KB；
7. 管道 ACL 只允许**当前用户 + SYSTEM**，并拒绝远程连接；
8. `open` 会还原缩入/最小化状态并置前。

### 3.2 期望你方保证

1. **忽略未知字段、未知 `type`**，不要因此断线（前向兼容）；
2. `state` 可能来得比较频繁（用户每次编辑都会保存），不要对每条 `state` 做重活；
3. `due` 里的 `content` 是**当前值**（用户可能刚改过），不要用缓存里的旧内容；
4. 同一 `id` 的去重计数按自然日重置（你们已实现）。

### 3.3 本期不做 `--headless`

原需求 §4.3 / §4.4 的"桌宠模式（无窗口、无托盘）"**本期不实现**——它与"`open` 要弹出窗口"自相矛盾（真无窗口就没有可显示的对象）。

- 桌宠侧**不需要**为 headless 做任何适配；
- 菜单"看看待办"在正常模式下照常工作；
- 若将来要做，会另行出方案，不会要求你们先改。

## 五、联调步骤（等我们 1.3.0 出来之后）

1. 先启动桌宠，再启动待办（顺序反过来也行）；
2. 桌宠菜单 30 秒内出现「看看待办」；
3. 在待办里新建一条 30 秒后到期的待办 → 到点桌宠说话；
4. 点「看看待办」→ 待办窗口出现且位于前台（判据：`GetForegroundWindow()` 等于待办窗口句柄）；
5. 关闭待办 → 菜单项消失；重新打开 → 30 秒内恢复；
6. 修改这条待办的内容和时限 → 到新时限时，台词使用**新内容**；
7. 两边各留一份日志（桌宠侧 `remind-state.json` + 控制台；待办侧 `%TEMP%\todo-go.log`），便于对时。
